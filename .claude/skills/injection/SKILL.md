# Injection 진단 절차

## 0. 입력 확인

- recon-agent 핸드오프에서 대상 파라미터/엔드포인트 목록 확보
- 목록에 없는 새 지점을 발견하면 먼저 recon 형식으로 기록 후 진행

## 1. SQL Injection

- 저강도: `'`, `"`, `1=1`/`1=2` 비교, 응답 길이·에러 메시지 차이 관찰
- 타이밍: `SLEEP()`/`pg_sleep()` 계열 (허용 범위 내에서만, 서비스 부하 고려)
- 확인되면 컬럼 수/데이터 노출까지는 진행하지 않고 "취약 신호 확인" 선에서 정지, 팀에 공유 후 필요 시 추가 진행 여부 논의

## 2. Command Injection

- `;`, `|`, `` ` ``, `$()` 등 구분자 + 무해한 명령(`whoami`, `id` 대신 `echo <marker>`) 조합으로 신호 확인
- 시스템에 영향 주는 명령(삭제, 다운로드/실행)은 사용하지 않는다

## 3. SSTI

- 템플릿 엔진 추정 후 `{{7*7}}`류 산술 표현식으로 렌더링 여부 확인
- 렌더링 확인되면 그 이상 확장(RCE 체인)은 팀 논의 후 진행

## 4. XSS

- 반사형: 파라미터 값이 응답 HTML에 그대로 반영되는지 확인, `<script>` 대신 무해한 마커 문자열로 우선 확인
- 저장형: 저장 후 다른 세션/페이지에서 렌더링되는지 확인 (별도 테스트 계정 사용)

## 5. 판정 기준

- `suspected`: 에러 메시지/타이밍 차이 등 간접 신호만 있음
- `confirmed`: 마커 문자열 반영, 산술 연산 결과 등 직접 증거 확보
- `false_positive`: 재확인 결과 신호 소멸 — 반드시 기록해서 중복 조사 방지

## 6. 기록

injection-agent 정의의 "기록" 섹션 형식을 따른다.

## 금지 사항

- 실제 데이터 변조/삭제 유발 페이로드 금지
- 대량 반복 요청으로 서비스 부하 유발 금지
- confirmed 판정을 재현 근거 없이 내리지 않는다
